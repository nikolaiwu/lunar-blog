# Deploying and publishing

## Demo site on GitHub Pages

The live demo is `https://nikolaiwu.github.io/lunar-blog/`, the sample posts built as-is.

- In `astro.config.mjs`: `site: "https://nikolaiwu.github.io"` and `base: "/lunar-blog"`. Read both from environment variables with those defaults, so template users can deploy to a domain root by changing one value, and document that in the README.
- **Every internal link and asset URL must respect `base`.** Use the one URL helper (see [architecture.md](architecture.md)). A hard-coded `/posts/…` works in `pnpm dev` at the root and breaks on Pages. Test with `pnpm build && pnpm preview`, which serves under the base path.
- The workflow `.github/workflows/pages.yml` follows the LunarCSS repo's: checkout, `pnpm/action-setup`, `setup-node` (Node 24, pnpm cache), `pnpm install --frozen-lockfile`, `pnpm build`, then `upload-pages-artifact` from `dist/` and `deploy-pages`. Copy the action versions from `../lunarcss/.github/workflows/pages.yml`. Deploy on pushes to `main`, since the demo should show the current starter, plus `workflow_dispatch`.
- One-time setup (the user does this): Settings → Pages → Source: GitHub Actions.
- No analytics in the template. If the user wants analytics on the demo only, add it the way LunarCSS does, at build time from a repo variable, so the template itself never ships it.
- `robots.txt` (generated by `src/pages/robots.txt.ts`) only counts at the root of a host. Under a base path like the demo's `/lunar-blog/`, crawlers look for `nikolaiwu.github.io/robots.txt` instead, and ignore ours. That's harmless, since it disallows nothing, but the sitemap line in it isn't seen either: submit `…/lunar-blog/sitemap-index.xml` in Google Search Console if the demo should be indexed quickly. At a domain root, both work as-is.

## Template install

Users install with:

```bash
npm create astro@latest -- --template nikolaiwu/lunar-blog
```

`create astro` downloads the repo's default branch as-is, so:

- Whatever is on `main` is what users get. Keep it building, and keep the lockfile committed.
- `.github/workflows/` ships too. The Pages workflow is useful to users; make sure nothing in it is specific to this repo beyond defaults they can change.
- Settle the open question in [brief.md](brief.md) about `CLAUDE.md` and `docs/` shipping to users before release.
- Test the real command in a temp directory before every release (see [CONTRIBUTING.md](../CONTRIBUTING.md#releasing)).

2. Live demo link and the install command

## Astro themes directory

Submit at https://astro.build/themes/submit/ **only when the user asks**. It needs preview images (take them from the demo, light and dark), a description, tags (blog, minimal, dark mode) and the repo and demo URLs. Check the current submission rules first.
